# PERF-02A-R2 measurement and extended-duration benchmark protocol

Status: implementation and CPU-only synthetic preflight; real GPU/long-film production acceptance still open. Use existing protected execution paths only. No owner project data, no extra admission authority, no automatic worker replay, no FFmpeg or security bypass. Workflow state remains in NVP_DATA_ALL_TASK_LEDGER.md.

## GPU observation semantics

Use existing trusted native resource sensors: Windows DXGI local process budget, Linux AMD DRM global VRAM and optional NVML global usage/capacity. Add local English Windows PDH GPU Adapter Memory and GPU Process Memory Dedicated Usage and Shared Usage, refresh provider objects before selecting instances. No remote machine, no subprocess, no subprocess PID opening. Owned-root sample originates from existing WindowsJobProcess live poll, verifies native handle PID and liveness before and after PDH read; no PID retained. First, last and sampled peak values (not physical guaranteed peak), independent per-source/per-scope/per-device, minimum observed budget. Retain at most 64 aggregate rows; 2-second interval plus explicit beginning/end samples; no continuous background thread. Windows PDH can lag and may not be available or accurate on all OS/driver combinations; English object names only. DXGI budget is scoped to the NVP host process, not worker VRAM capacity. AMD DRM and NVML capacity are not Windows process budgets. PDH root sample is NOT child process tree accounting. Do not sum overlapping global and process sensors, or map DXGI index and PDH LUID by order. Preserve missing counters as null; do not turn missing provider into zero. No project/source identifiers, paths, PID or exception contents. Sampling is optional inside a trusted observation session; ordinary production disabled by default; synchronous sampling may add latency in observed runs. Qualify poll/cancel timing on real Windows hardware before considering any always-on telemetry. Existing selected-view Cycles script explicitly sets scene.cycles.device="CPU"; CONV-12 proves CPU native pixels, not Radeon rendering.

## Reproducible local benchmark

From repo root: python -m tools.nvp_perf_benchmark. Five trials, 200 operations per mode, rotating mode order, same deterministic no-op and SHA-256 over fixed 64 KiB; check output identity. Measure median wall ns per call including setup and teardown; compare direct, wrapped disabled, host only and host plus GPU. Save full trial data, not only median. Actual 2026-11-18 Linux/Python 3.13.5 CPU-only raw evidence in performance/2026-11-18-perf02a-r2-local-synthetic.json. No real GPU visible. Exact final run host overhead ~60.23 us/no-op and ~65.49 us/hash over direct; unavailable-sensor GPU-enabled path ~66.59/~67.00 us. Disabled no-op delta 69.25 ns. Real driver timing not measured. Roughly equal noisy timings do not demonstrate zero overhead. This is synthetic arithmetic and hash timing, not native render throughput.

## Native acceptance plan

1. Reconcile original unchanged-SHA DATA-AV, WO4, CONV-12, SLATE-05 and remaining mandatory cohorts. Reuse original same public-fixture test suites through tools.nvp_perf_acceptance; no second CI run is required solely to collect telemetry. Ordinary CPU-only runner may report no GPU; on qualified hardware use --require-adapter-sample to demand an observed adapter-global memory reading (not physical GPU render qualification by itself). Record selected GPU/driver/backend separately with hardware owner, match device identity, stable idle state first/last, exclude unrelated GPU workloads. Validate PDH against Task Manager/driver utility; record actual renderer backend and independent native pixel/PCM receipts. Never claim GPU execution from memory allocation alone.
2. Fix fixture seed, source clip/actor/scene diversity, resolution, sampling and quality settings, exact source SHA, device and OS; compare same workload in observation-off/host-only/host+GPU runs, cold versus warm cache. Record wall/CPU time, verified frame throughput, process lifetime peak RSS, native Job peak commit, adapter-wide dedicated/shared and worker-scope values, storage transfer bytes, cache hits/misses and sample time; record source receipt coverage, I/O semantics, unavailable data and cancel latency. Separate host sample overhead from rendering work. Do not infer full film rendering from small representative spans.
3. For each duration, first generate a synthetic bounded source/shot planning fixture, measure plan publication, first/middle/last page read and paginated full reconciliation; cross-reel/split-shot boundaries; cold/reopened project, cancel and hard host death while real worker is active, independent reopen and no unauthorized replay. Compare duration scaling without preallocating per-frame images. Then render fixed representative windows of identical complexity/length at beginning, middle and end, record derivatives and bounded memory/disk. Only full original coverage and delivery receipt may declare actual duration accepted.
4. Separate engineering gate before 3 h / 6 h native plan or full production: change existing duration and chunk constraints only after audit of typed bounds, schedule and ledger scalability, memory budget, PCM/container limits, file-system output and crash-safe streaming, and security/creator authorization. Retain exact existing safety gates. Include at least 3h and 6h in actual physical benchmark after redesign; never set a filmmaker duration cap merely to simplify the test.
