# USD-FILM-01F — from immutable original world Digital Takes to native Blender/Cycles frames

**Status (2026-11-08): FIRST source/render implementation, actual native OS tests, real Blender integration test and independent .blend reopen checks COMMITTED; completed exact-head Windows/Linux/Blender execution evidence OPEN.** Stacks on HSURF roadmap PR #133 and 01E original-world source Take. This work remains filmmaking only.

## Why this matters

01E correctly separates a persistent OpenUSD world and the director's immutable camera-shot/performance source Take from generated picture and sound. However, the old `FrozenSceneAV` and Blender workers consume older scene-only Take formats: they cannot be claimed to have rendered `nvp.usd_film01e.immutable_composed_world_take.v1`. **01F explicitly starts bridging that source format to actual reviewed Blender/Cycles execution** without replacing original performers, authoring substitute geometry, or treating authored USD as rendered pictures.

## Implemented initial source → real-picture pipeline

**Host:** `backend/nvp_usd_film01f_blender_host.py`

- Reopens **two distinct frozen 01E world Takes** from the same **exact original world revision**, verifies source Take, associated distinct 01D camera shot, original world, StoryBible actor casting, original audio event/PCM, immutable SHA and checkpoint integrity by calling the existing 01E verifier.
- At each exact stored film tick, opens the real original world, loads only the required named scene set(s) through the verified 01C payload cache, applies existing original camera/look source, checks the real native USD camera and each ActorID's authored 3D geometry. Rejects an actor made only of an empty Xform (NO visual proxy substitution).
- Derives a **throwaway one-frame flattened USD stage**, evaluating authored USD animation and setting values at the exact requested Film Time. The source USD and original world Take remain unchanged. Reserializes and independently reopens the derivative USD, requiring the same camera and actual actor geometry. It is deliberately a **single-frame render build** (NOT yet a genuine moving multi-frame sequence) and no original actor pose is regenerated by Blender.
- This first host rejects unresolved external texture AssetPaths. Arbitrary renderer-supplied file paths / image fetches and unreviewed MaterialX file substitutions cannot be silently accepted. Complete 01C material bundles and precise MaterialX shader/color parity remain follow-up parts of 01F/05/08.
- Binds the two original Take SHA, camera shot SHA, original world SHA, actors, selected exact tick, source file SHA and original audio event count into two structured render packets; requires a genuine **host-authenticated director render action** referencing those exact SHAs. Never permits an AI-supplied renderer script, arbitrary Blender binary or unbounded worker.
- Uses the existing `BlenderWorkerSupervisor` with pinned native Blender executable/script/file hashes, contained OS execution, durable worker journal, output media checks and cancellation/recovery. No new actor generator, renderer or Model Control Protocol requirement.

**Real Blender:** `tools/nvp_usd_film01f_blender_worker.py` (GPL Blender-side script)

- Loads **the actual saved source USD file** via Blender's real `bpy.ops.wm.usd_import`, checks source SHA, real imported geometry, named original actor roots, original native camera and its world position; **does not add a fake camera, fake actor mesh, proxy character or invented motion**.
- Renders an original 320×180 **CPU Cycles** frame with 12 samples, writes a real PNG, saves a native `.blend`, returns a SHA-bound audit (imported geometry/camera/light counts, exact Take/shot, original actor count, native Blender version, PNG/scene hashes). These low-sample frames are engineering output, NOT cinematic photoreal or final movie output.

**Second independent Blender process:** `tools/nvp_usd_film01f_blender_reopen.py`

- Reopens each first worker's real saved `.blend` under a separate SHA-pinned, journaled Blender operation. Rechecks original world/Take/camera SHA tags, exact sample tick and original ActorID identities, ensures actual source geometry and saved camera still exist. Returns independent JSON audit. A success from the first worker alone **cannot** satisfy this initial two-shot gate.
- Both workers are approved, fixed scripts. Their Blender-side GPL licensing remains an independent native redistribution/compliance review before release.

## Native source fixture and CI

`tests/test_nvp_usd_film01f_world_render.py` uses NVP's **existing authored 30-second three-shot Donut/Box/Sphere/ServiceCraft original film sources**. It creates one persistent world containing **two exact original scene revisions as independent named sets**, with their original source Take IDs, four canonically cast StoryBible ActorIDs linked to both older Takes, different 01D original source camera-shot plans and two new immutable 01E world Takes. Checks that:

- Both new 01E Takes are independently reopened/verified and originally sampled at exact source time.
- The derived source USD snapshots reopen with **the actual original torus mesh's 504 vertices** (not a new primitive donut), the four original actor IDs and true original cameras. Two different original world shots must not be replaced with one generic scene.
- Original source Take SHA and original PCM event provenance remain unchanged; no audio is synthesized or mixed merely to render source frames.
- Wrong film project, missing original source tick, missing geometry, substituted camera/ActorID or unverified source fail closed instead of claiming usable film.
- When a genuine Blender executable is supplied, two real CPU Cycles pictures and two independently reopened `.blend` sources must pass. A real frame can still be visually poor and must be reviewed.

`.github/workflows/nvp-usd-film01f-native-world-render.yml`:
- Four native `usd-core==26.11` source/casting/Take tests on Windows 2025 / Ubuntu 24.04 × Python3.11/3.13 (includes 01E regression).
- A separate actual official Blender **5.2.3 SHA-verified Ubuntu** job that renders **two source frames** with actual Cycles and two independent fresh Blender reopen passes, uploads PNG, .blend, original source USD and original/independent audits.
- Source job success does not imply Blender import success; a queued/cancelled job cannot count toward acceptance. Inspect actual exact-head logs, media and renderer settings and repair genuine failures. Standard hosted CI does not prove installed desktop Windows GPU performance or visually acceptable human filmmaking.
