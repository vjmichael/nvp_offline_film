# PERF-03C — Durable paginated production-source verification

## Scope and guarantees

The existing encrypted ProductionJournal has an additive v2 format, nvp.wo4.production_job.paged.v2, for its existing VERIFY_APPROVED_MEDIA_V1 read-only worker. No new renderer, native executable, codec, output publication, DCP authorization or retry permission. Legacy v1 manifests retain their original bytes, hashes and worker semantics; no destructive migration or silent rewrite. Writable existing native journal initialization creates the new page table; read-only review never migrates. Long jobs can be submitted by trusted NativeProductionHost.submit_verification_pages (new explicit creator operation) using a replayable source-page factory. Old submit remains the existing legacy API. The host must supply authenticated creator approval of the exact root and FilmIndex revision. UI wiring and output-producing cinema/feature manifests are separate.

Each page retains at most 64 canonical, contiguous source intervals with exact position, source path, byte length and SHA-256; max 256 KiB encoded and at most one million positions per job, checked prior to visibility. A root document contains source assembly/dependency identity, exact time interval, count, page count, page size, SHA-256 of concatenated ordered binary canonical page hashes. Page hashes are independent of transient status rows. After consent a second factory pass must produce exactly the same root; same assembly is rechecked before and after, protected source bytes independently reopened, and root, pages, operational segment records and the submission event commit together in the existing WAL/FULL transaction. A partial or changed second pass rolls back. Approval is source verification only and never authorizes rendering, codecs or export.

All original claim/finish checks stream every page and compare every committed source row including tail; missing/extra/reordered pages, altered canonical JSON (including rehashed pages), missing/extra/substituted rows and incomplete clock coverage fail closed. Full status for v2 returns first 64 positions and continuation, or an explicit <=64-row status_page; v1 full status is unchanged. Read transaction reuses existing protected Desktop Review snapshot if already open. Worker admission remains exactly one live lease globally under the existing native owner guard and existing task allowlist. Fast cancel query verifies live read-only job and segment owner token and state, so verification blocks no longer reparse the root on every cancellation poll; claim and finish still independently audit the full manifest. Unknown task kind is not authorized. No change to other native cinema worker paths.

Restart reopens immutable source root before bounded keyset SQL pages of up to 64; interrupted read-only verification can return to PENDING under existing supervisor custody, never output-producing work. Recheck actual verified source bytes; altered data requires creator review. Report first 64 affected positions and exact counts for v2, full durable events for every position; legacy report preserved. Reviewed retry streams source digest checks and compares exact ordered review-set SHA plus count in final transaction; existing source-bound creator approval still required. No file deletion, no automatic rendering, unchanged native singleton owner and EFS storage guard. Recovery remains atomic in one existing write transaction; full approved source page set is still checked. The bounded-memory design is not a claim of constant-time admission: full verification is O(number of source entries), and synchronous publication and recovery can hold a long write lease. Job catalog and recovery result arrays are per-job, not yet paginated across all jobs. Native throughput, cancellation timing and actual storage quotas still need physical qualification. Root integrity is within the original protected journal trust model, not an external signed audit.
