# USD-FILM-01D — director-camera-aware native OpenUSD shot working sets

**Implementation date:** 2026-11-08. **Source and native Windows/Linux tests committed; actual current-head native acceptance OPEN.** New branch stacked on USD-FILM-01C PR #130. This is purely filmmaking. Existing 01A–01C source/texture/asset verification remains distinct; FILM03-09E actor lip sync and USD-FILM-01E/F original-world Digital Take/rendering remain open.

## The useful recommendations from the creator's Claude review

The supplied Claude OpenUSD note describes (1) keeping the rich USD scene authoritative while producing a validated, target-specific *compiled* view, and (2) letting AI use small **typed USD operations**, an isolated stronger edit layer, reversible diffs, bounded scene summaries and source validation instead of writing raw USDA. Those ideas fit NVP's existing FilmIndex and supervised native execution model.

**Adopt now:** A camera shot is a typed FilmIndex `camera` record; a source-locked shot **working set** is a disposable derived USD view. An AI/director can ask the host to select an original shot, inspect the bounded scene summary, and change only verified original look variants in a **separate anonymous Stage session-layer opinion**. That layer is removed on undo or shot change. Original FilmIndex world, actor, camera, Takes, assets and authoring layer SHAs do not change.

**Adapt later:** A film rendering build/compile step should resolve the chosen original shot, original camera, approved material/shader look, asset and time variants, and validated renderer outputs, then produce a renderer-specific evidence report. It must check original source → Blender / Hydra (where supported) → real image/audio before acceptance. Reuse OpenUSD's actual `usdchecker` only if available in the installed toolchain. This is primarily USD-FILM-08/09 and source-to-master acceptance; no headset/profile conversion or interactive object behavior belongs in 01D.

**Do not adopt:** VR headset, WebXR/glTF, standalone headsets, collision-for-grabbing pipelines, a game runtime, historical/digital-twin reconstruction, or mandatory MCP server. Existing NVP native host tools are the default.

## Host implementation

`backend/nvp_usd_film01d_shot_working_set.py` adds:

- `FilmWorldShotPlanner.publish(...)`: creator/director-shot plan is bound to one **exact** published NVP `world` revision and an exact original camera scene ID, revision, camera prim role/path and scene SHA. The planner opens the genuine composed USD stage, loads only the camera set, and **reads the actual UsdGeom.Camera transform at 1–16 exact original Film Time ticks**. Sampled camera positions are recorded in the durable FilmIndex `camera` document. Source time has 7,056,000,000 ticks/s. Plans cannot name fabricated camera geometry, cross-project sets, unknown look variants, repeated/out-of-order ticks, or budget-unsatisfiable scene selections.
- **Mandatory vs proximity distinction:** The camera's own set and every director-`required_sets` item are mandatory. An optional `spatial_hints` list with bounded 3D centers/radii can suggest additional sets inside a bounded distance from actual sampled camera positions, subject to an explicit maximum loaded-set count. **Hints are NOT proven visual bounds**, scene culling, a complete camera frustum or occlusion test. If the budget cannot hold every required original set, the shot is refused; distant original required sets are never discarded.
- `FilmShotWorkingSet.transition(...)`: existing original project WorldSession performs actual native OpenUSD payload unloads and loads, staged source verification and actual original camera resampling. Drops non-required prior sets to enforce the typed count cap, then opens the required next shot; verifies the native camera samples have not drifted. Optional prefetch may be omitted when the budget is full. A successful transition writes a source-bound FilmIndex `presentation` receipt. This is a **data working-set receipt, NOT picture, UI, performance or final-film acceptance**.
- **Isolated creative look layer:** Only existing source-authored USD variant names and choices can be applied, through `Usd.EditContext` on a new anonymous layer **under the Stage's stronger session layer**, not the world root. `discard_temporary_look()` removes it. The derived opinion layer is disposable and its SHA is recorded, while old FilmIndex source document hashes remain the same. A new shot begins with a fresh layer so another shot's director look does not leak.
- **Small semantic query:** `query_loaded_scene()` lists at most 128 loaded original prim paths with their authoritative FilmIndex role (camera/actor/prop etc.). This avoids dumping a huge scene into a small local AI context. This is a role query, not proof of unique ActorID/VoiceID associations or genuine object occlusion.
- **Measured budgets:** Optional strict whole-process RSS budget, sampled from the existing native Windows/Linux `_rss_bytes()`, refuses progress if actual measurement is absent or over limit. An optional GPU callback is available; `native_gpu_device_sampler(device_id)` uses the EXISTING NVP `collect_resources()` source and distinguishes device-global DRM/NVML readings from the Windows DXGI process/video-budget readings. The GPU callback is required if a device budget is configured; no GPU sensor means **no fabricated VRAM number**. Neither device-level nor process-level GPU reading is attributed solely to the USD Stage. The existing NVP resource ledger remains the correct authority for separate heavy-worker admission; this module does not spawn another rendering process.
- **Interruption and recovery:** A trusted host cancellation callback aborts the transition. If an exception occurs after partial USD loading, the entire private temporary session is closed (rather than reusing an uncertain stage). The FilmIndex presentation receipt records `INTERRUPTED` or `FAILED`, never a false pass. Recovery is **new** verified project-owned USD session + exact saved shot plan + a new receipt identity, not resurrection of a background process. No external worker/process was spawned in this layer; claiming OS descendant cleanup would be false.

## Native tests and measured acceptance

`tests/test_nvp_usd_film01d_shot_working_set.py` exercises genuine native USD original cameras and existing first-party FilmIndex scenes. Covers: exact source camera positions and times; outside → inside shot change; actual unload/load; director preview look in isolated native Stage session layer and undo to original; required-distant scenes; optional near prefetch; denied insufficient set count; bounded source role summaries; original FilmIndex SHA; cross-project and fabricated-camera refusal; explicit cancellation persistence; independent SQLite/Studio restart; strict RSS sensor failure; strict GPU callback refusal; and labeled, **synthetic-only** DXGI/NVML sensor scope contract tests. Hardware sensor stubs are not passed off as native measurements.

`tools/nvp_usd_film01d_benchmark.py` makes a real two-scene original film world with cameras, actors and 1,200 PointInstancer positions, publishes original source-locked shot plans, then performs **20 actual alternating OpenUSD shot transitions** through a newly opened Studio and FilmIndex, measuring wall time per shot and whole-process RSS. It persists interruption and tests fresh source-bound restart. The JSON labels unset GPU, unmeasured installed UI FPS and unrendered/unaudited picture. It is source performance evidence only.

`.github/workflows/nvp-usd-film01d-native-shot-working-set.yml`: 4 genuine native USD regression cells (Ubuntu 24.04 / Windows 2025 × Python 3.11 / 3.13), plus a separate real 1,200-instance / 20-shot benchmark on **both OSes**. Tests include 01C source/MaterialX/texture and 01A original frozen scene/Take regressions. Benchmark JSON artifacts preserve source SHA, per-shot loaded sets, source cameras, cancellation/restart, process memory and elapsed time. No GPU device is required on standard CPU-hosted Actions.
