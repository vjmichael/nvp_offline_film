## CAM-FX-03 — actual interactive rail editing

### Source-coordinate 3D gizmo

- `frontend/src/CameraRailGizmo.jsx` adds an orbitable, zoomable, **interactive orthographic 3D projection** inside the existing installed `CameraRailsDirector` view. The camera control points, look-at targets, and tangent handles can be moved via pointer gestures; keyboard arrows move metres in the original XY plane, Page Up/Down adjusts camera/target Z, and the host receives finite, typed source-coordinate handles. No physics collision is generated or assumed. The gizmo does not synthesize actors, render movie pixels, or replace the proper offline USD/Cycles camera.
- It overlays bounded **actual source ActorID boxes only after first-party native OpenUSD receipt**. At startup or without trusted source context, it displays editable rail controls with no invented actor geometry. Tilt/orbit/zoom are view-only; they do not rewrite performer transforms.
- The existing numeric editor still allows exact Film Time retiming; insert, remove, undo, focus, focal length, f-stop, filmback, roll, source-origin rebase and incoming/outgoing tangent edits. Draft is revalidated after every change before approval. Typed starting presets remain source-editable (dolly, crane, orbit, OTS, POV, reaction, Dutch, rack focus, dolly zoom, etc.). Presets are NOT proven framing or depth-of-field effects.

### Actual source ActorID framing and conditional district center-ray checks

- `backend/nvp_cam_fx03_source_guidance.py` calls the first-party 01M camera bank and immutable 01E world Take authority. It opens the original OpenUSD world, loads the existing scene Takes, reads real `UsdGeom.BBoxCache` world bounds for 1–24 verified source ActorIDs at three exact Film Time samples, and computes screen UV framing using the same Z-up / USD-camera-look-`-Z` geometry used by the rail authoring path.
- The filmmaker may select one verified ActorID and optionally one exact **approved 02M-H original district shot binding**. The host independently checks that the district and world source belong to the same original Take. It imports the bounded 02M-E2 source-approved visible building mesh renderer view, reads actual triangulated USD geometry/world transforms, and checks the selected actor's *camera-center ray* against bounded original/district source triangles. The receipt identifies an actual hit source prim when detected and records non-mesh exclusions and work limits.
- A single ray with no hit is **not full-frame visibility proof**; partial nonmesh coverage is clearly flagged, and an intentional through-wall director camera remains possible subject to an explicit human view-quality decision. This native source checker does not automatically remove world geometry, hide actors, claim transparency, or fake a rendered shot. Real visual occlusion, highlights, depth of field and shadows need CAM-FX-05 native Cycles evidence. Real actor limb/face tracking and a full shot composition grammar are still improvements, not falsely inferred from an ActorID bounds center.

## CAM-FX-03 — interruption-safe original director drafts

- `backend/nvp_cam_fx03_durable_drafts.py` is a host-owned, project-scoped **SQLite WAL FULL synchronous** source journal under NVP's existing private WO5 app directory. Each draft pins exact rail ID/source revision, current source SHA, original frozen Take SHA, normalized typed rail controls, native preview and separately generated stronger USD layer SHA; operations use `BEGIN IMMEDIATE` and CAS version checks. At most 24 undo snapshots and bounded project catalog rows.
- Source-validated draft create, save, durable undo, discard and reopen are exposed through existing trusted installed WebView2 host methods. The React director acknowledges native edit commits and autosaves after the input settles. Edits still being dragged/in-flight are explicitly *pending* until acknowledged; no claim of persistence before the SQLite commit.
- A draft publishing attempt records **PUBLISHING with native host-session identity** *before* a separately scoped OS confirmation. It cannot become an implicit capability. On a different installed process restart, an unfinished attempt becomes **INTERRUPTED_REQUIRES_NEW_APPROVAL**. The host may read-only reconcile an already existing and SHA-matching authoritative FilmIndex commit, but NEVER replay the OS dialog or run an earlier publication worker from old permission.
- AI models cannot revise a draft while the director has changed the draft version. Model advice is admitted with current project/draft/version/source-context SHA; cancellation, source revision changes and old host sessions reject late outputs inside the same SQLite transaction that would otherwise update the draft. A successfully generated model suggestion appears as **DRAFT_UPDATED_UNAPPROVED**, retaining durable revision/undo and model provenance; it cannot auto-publish.
- UI source catalog supports reopening project-local drafts after app restart; local editing can continue on a current unapproved source revision. An interrupted publication requires a *new* draft/new decision if no exact FilmIndex commit is independently found. Manually published older rail versions remain immutable.

## CAM-FX-04 — actual local AI advice without model authority

- `backend/nvp_cam_fx04_model_camera_candidate.py` sends the selected **existing WO6 host-owned loopback** model an explicitly bounded prompt with verified source ActorID geometry/framing, optional approved district SHA, actual original Take SHA, exact source bank, three authored Film Time samples and director intent.
- Candidate output must be a single strict JSON object: `{"technique":"...", "nodes":[...]}`, 2–4 typed control nodes, strictly ordered original integer times and unchanged first/last Film Time. The host fills only first-party approved non-creatively selected defaults (e.g., original f-stop and zero tangents), then invokes the same native bounded `normalize_rail` and independent USD source preview. Rejected: arbitrary USD paths, source Take/ActorID substitutions, OS/worker commands, unknown techniques, NaNs, excessive speed/acceleration, untrusted frame/time shifts or extra fields.
- `ProvenLocalModelWriter.complete_camera_candidate` reuses the existing reviewed strict response-format grammar, model endpoint and provider receipt. The provider's reported tokens/model name and generated text SHA are **provider self-report**, not cryptographic proof of model weights or real inference. The separate real GGUF acceptance must hash the actual model/llama.cpp server binary and observe valid source JSON in installed NVP.
- `backend/nvp_cam_fx03_04_desktop_mixin.py` reuses NVP's exact-origin desktop bridge, existing trusted model factory, bounded daemon-thread generation, cancellation, per-session admission and SQLite attempt status. This is a typed proposal writer, not a new AI tool server or mini-app. Any model suggestion remains fully editable by the director and requires new source preview **and native human OS approval** to become an immutable camera layer.
