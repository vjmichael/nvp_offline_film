## INT-01C — Studio, FilmIndex, G06–G09 source and authorization (source authored)

**Source architecture decision:** Canonical DA-03 FilmIndex `take` revisions and director G06 Studio/LiveFilmStore frozen Takes are **separate authoritative source namespaces**. Equal project/scene IDs or elapsed time alone do not establish byte-equivalent OpenUSD or original audio. **No canonical Take is rewritten, deleted, silently converted, or copied into the encrypted project store**. Any future conversion of arbitrary FilmIndex scene/UsdSkel/timing assets into the filmmaker's G06 render schema requires independent replay and original-byte comparison; it is **not yet implemented**.

**Implementation on the Wave 1 branch:**

1. New `backend/nvp_int01c_source_contract.py` creates a deterministic SHA-256 **G06 original source binding** containing project/scene/Take namespace, original stage revision and SHA, OpenUSD original/performance SHA, exact integer Film Time/tick rate, actor/stage roster/event/setting digests, and each original PCM source/ActorID, 48-kHz mono sample count, sample-tick duration, scene-time offset and long-recording/legacy/sealed source provenance. Source identity metadata is checked without flattening or changing recorded source bytes.
2. G06 `freeze_take` checks the contract **before** the authoritative immutable row is published. Both `_take_metadata` and `_take` revalidate it on reopen; the metadata reader now independently checks underlying SQLite sample rate, channel count and exact original-source kind in addition to ActorID, PCM SHA and byte count. Existing G06 SHA-verified USD and ordinary/5s sealed PCM readers retain their independent media authentication and fail-closed ciphertext handling.
3. Trusted host-only G06 `compare_canonical_source` accepts a reviewed FilmIndex in the **same physical Studio database** with an explicit host-supplied ordinary-project authorization callback. It independently verifies the canonical DA-03 `OpenUSDTakeCapture` source revision, reports namespace, SceneID/Film Time correspondence and SHA evidence, but explicitly returns `same_original_source_proven=False` and `may_edit_as_same_take=False`. Protected G03 projects categorically refuse ordinary FilmIndex access.
4. G07 `native_assembly` maps validated Take bindings into a project-scoped hashed source-provenance map for **every referenced original Take**, while loading source bytes only for participating film windows. Its separate G09-D finishing `source_bindings` map is untouched. Independent verified studio/original scene data, edit SHA and immutable Take SHA remain bound to director versions.
5. G08 native short export, protected in-memory export, G09-E ordinary long-worker start/resume/child, protected sealed long-window preparation, native MJPEG/PCM render and checked ten-second reels now verify the source-provenance map and original source bytes/PCM fingerprints before deriving pictures/sound. Full render audio retains its 48,000 sample/sec Film Time mapping and independent source readers. The protected AppContainer child refuses missing G06 provenance except for the **existing explicit, CI-only one-frame synthetic W1-F fixture**; that exception provides **no human approval or sandbox authority**.
6. `tests/test_nvp_int01c_source_contract.py` covers valid exact integer source clock, stage and ActorID lineage, original USD tampering, PCM/emitter substitution, cross-film/cross-scene/manifest SHA swaps, rogue G06 DB sample rate/channel values, untrusted FilmIndex access and unauthorized private worker source admission. These tests are written but **not run** on the new source head.

**Still open / explicitly not claimed:** canonical FilmIndex → G06 direct editable scene/Take **conversion** (there is no proven identical OpenUSD/source-audio bridge); physical microphone/hardware clocks and cinema performance; DA-03 actual Linux kernel custody integration, missing secure Linux filesystem/network confinement, encrypted original orphan cleanup, full 30–180-minute sustained source windows, owner-installed Windows and Linux acceptance, historical migration, and Lu shared model/authority. The G07 source map is a host-verified source compatibility guard, **not** a license to bypass project grants or to publish a model-proposed revision.

**Next:** **INT-01D** Lu-owned Workspace host handshake and proposal-only creative runtime source integration, while retaining canonical FilmIndex conversion as a separately tracked INT-01C compatibility obligation for a future renderer/importer. Keep W1-F certified only at `8f743784`, not this new untested source commit.

## INT-01D — Lu-owned model readiness, proposal-only inference and Film Home integration

**Source integration authored; real external Lu Workspace connection not yet established.** Draft [PR #154](https://github.com/vjmichael/nvp_offline_film/pull/154)'s `LuG02FilmPort` and its complete generated-event/receipt regression fixtures were selectively brought into the current Wave 1 source. The port preserves real host-owned `verify_scope`, model/session/epoch, complete ordered generation events, receipt journaling and one-time exact-proposal consumption. Its project validator now handles ordinary NVP 32-digit lowercase hexadecimal project IDs, including digit-leading IDs, without weakening scope equality. Neither the port nor NVP loads GGUF, makes network requests, launches llama.cpp or creates a second model.

**Native host admission:** `backend/nvp_int01d_lu_host.py` accepts an externally supplied, native Lu-owned `NativeLuHostPort` and `issue_scope` callback through a **Python-only** `install_native_lu_film_service()` bootstrap hook; **no HTTP/JavaScript scope issuer or registration route exists**. Every Lu status, project read, generation, receipt, save and cancel is scope/epoch/project checked by the Lu adapter, with a separate exact NVP project ID and local lock/session recheck. **Installed Lu 0.1.0-alpha.2 has only internal Tauri status/inference, no proven externally accessible native NVP Workspace interface**. Therefore NVP does not invent a loopback socket or self-install the host; status remains `disconnected` without a genuine Lu provider.

**G04 proposal handling:** The host may only return a completed, durably journaled proposed screenplay. `NvpLuWorkspace` has a strict production completed-receipt mode: it verifies exact normalized content SHA, proposal-only outcome and no source mutation; the older separate development harness remains explicitly non-production. `G04Preproduction.stage_lu_screenplay` saves a new `proposed` G04 screenplay draft under the current film's SQLite `BEGIN IMMEDIATE` revision/source CAS. The existing G04 **human Approve/Decline** route alone can change the screenplay, with original source revision history preserved. Failed, incomplete, cancelled or stale requests must leave the source untouched. A Lu-side completed proposal whose local mirror CAS fails remains an unresolved Lu-side proposal; no model is falsely reported as having updated the NVP screenplay.

**Director interface:** The real `FilmmakerHome.jsx` now displays **per-current-project Lu** ready/busy/loading/unloading/failed/unloaded/disconnected status instead of inferring readiness from `/api/creative/models`. `DirectorScreenplayAssistant.jsx` gates its Ask Lu action on project-scoped `/api/projects/{id}/lu/status`; its existing screenplay-proposal endpoint is now Lu-host-only rather than calling G04's independent `_local_writer`. A host-confirmed cancellation request is exposed without claiming confirmed generation termination. The rest of the filmmaker creative/edit/film workflow and manual screenplay editing remain available while Lu is absent. **Scene-idea, 3D-stage-idea, performance-note and Post-Production editing-idea UI** now also observes the Lu-native **project-specific typed capability list** instead of the legacy generic model port; those optional AI controls stay disabled until Lu explicitly supports their respective operations. Manual Set Up Scenes, actual 3D stage authoring and Film Scenes controls remain enabled. Direct legacy specialist backend AI endpoints still exist for compatibility and must be migrated or explicitly retired in a later work group; no second model process was created in this integration.

**Confidentiality:** G03 encrypted live films **categorically refuse the external Lu project source path** until an actual no-egress/secret-free source contract and user-approved trusted Lu access are implemented. The existing NVP private-film lock, DPAPI/AES-GCM, W1-E AppContainer and original Take authorization are not downgraded. A spoofed browser-supplied Lu scope or local model endpoint cannot install an AI host through an API request. No Lu model-generated text can authorize tools, cameras, rendering, worker launch or freezing a Take.

**New source tests:** `tests/test_nvp_int01d_lu_film_home.py` exercises exact NVP/Lu project scope, ready/busy/unloaded state, stage/approval and decline, source-revision race, revoked/foreign project, incomplete generation, cancellation, protected movie refusal and native host installation ownership. PR #154's `tests/test_lu_g02_film_port.py` covers original Lu event/receipt invariants. These fixtures are **authored/imported but not yet executed** at the INT-01D head.
