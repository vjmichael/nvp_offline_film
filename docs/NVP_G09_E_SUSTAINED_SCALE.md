# G09-E — Sustained-Scale Film Rendering and Recovery

**Implementation branch:** `nvp/g09e-sustained-scale-20261111` stacked on G09-D. **Engineering state:** native source implementation authored in GitHub, but **no exact-head compiler, CI, installed Windows/Linux, 30-minute or feature-length actual run was executed** under the director's build-first workflow.

## Goal and genuine implemented boundary

G07's source-referenced film editor can describe up to eight hours, but G08's native AVI export is a genuine **30-second / 24fps / 48k stereo / 640×360** bounded delivery. Simply increasing the G08 AVI counter would overflow its 32-bit RIFF/media budget and would not solve full-film PCM memory, process interruption, original source custody or accurate audio mastering.

**G09-E creates a separate native reel delivery profile**, using exact 10-second/240-frame chunks, each a playable real G08 MJPEG/PCM16 AVI, and a separate cryptographically audited ordered manifest covering the entire film. A three-hour film would contain at most **1,080 reels** and precisely **259,200 picture frames** and **518,400,000 original-derived stereo audio samples per channel**. The editing clock stays **7,056,000,000 ticks/s**; every reel has authoritative global picture/sample start/end. This is *not* a single gapless master or cinema DCP. G09-F must assemble a user-friendly portable delivery experience, and real physical uninterrupted playback remains to be demonstrated.

## Source implementation inventory

**E1 — Original media windowing**
- `backend/nvp_g06_filming.py` adds `_take_metadata`, validating the immutable Take source identity, audio object IDs, actor binding, SHA fields, clip count/length and scene-document hash **without loading all original USD and microphone blobs**.
- `backend/nvp_g07_edit.py` adds a host-only `native_assembly(...,window=(start_tick,end_tick))` accepting only up to ten exactly aligned seconds; it preserves the full edit SHA, every approved scene/actor/acoustic/finishing SHA and all Take identities while loading original USD/PCM only for Takes contributing to the window. **Each contributing original USD and PCM is fully hashed against its frozen source record before rendering**. Thus metadata validation alone is not incorrectly claimed as full-media validation. Each participating source window has a **256 MiB admitted media budget**, each PCM clip is limited to 64 MiB in this initial reader, and source Take count per window is at most 24.
- Critical G09-C integration fix: an approved acoustic review object previously reused the `sound` variable and could displace original PCM in `native_assembly`; original audio and `sound_review` are now separate.
- `backend/nvp_g09d_finishing.py` uses Take metadata for film-wide source binding rather than loading and reopening potentially hundreds of original performance/audio blobs on every approval.

**E2 — Genuine streaming sound and one film-wide mastering decision**
- `backend/nvp_g09e_audio.py`: bounded 1-second stereo PCM feed, continuous 48k K-weighted filters and 100ms/400ms BS.1770-style integrated-gate measurement, absolute+relative gating, original sample peak and a conservative full-film gain/ceiling/fade plan. Each output reel applies the **same** approved film-wide gain and exact global-sample fades. No per-reel normalizer, invented audio source or codec substitution. Full rendered PCM is measured **again** when all verified reels are finalized. For review-grade finishing, a missed approved target blocks final publication. **True intersample dBTP is not measured.**
- A bounded Python fallback supports up to ten minutes of film analysis; meaningful >10-minute production needs vetted, installed **NumPy/SciPy native accelerated DSP**. The host checks this *before enqueueing or resuming* a longer work order and fails with a clear message if absent. The foundation/installer does not yet attest the optional accelerated runtime; **G09-F needs to package/approve it**.

**E3 — Native working-video segmentation**
- `backend/nvp_g09e_chunk.py`: exact source-based picture rendering of G06/G07 cameras/performances and approved G09-A/B looks, 48k microphone-derived sound including G09-C approved 3D acoustics, G09-D approved SDR picture settings and film-wide PCM mastering. Every **240-or-fewer-frame AVI** is bounded to **80 MiB** and carries original-source digest, exact start/end Film Time and 2000 stereo sample count per frame. Actor movement/face is evaluated from source at each picture moment; this first long-reel path does **not** pretend it authored and independently opened a feature-length UsdSkel layer for a single three-hour Take. That advanced G09-B/E requirement remains open.

**E4 — Durable native worker custody and restart recovery**
- `tools/nvp_g09e_worker.py`: fixed-worker actions `analyze`, `render`, independent `verify`, `finalize`; no FFmpeg, shell, arbitrary network/code/path, or model-granted permission. Analysis is full-program before any actual reel, not fabricated loudness. Each reel is genuinely produced from source, then **a separate worker independently reopens and decodes the AVI and verifies every frame, PCM clock and digest**. Finalize reopens and hashes **every completed published reel** and measures the concatenated actual output PCM. The final manifest contains ordered relative reel filenames, all SHA-256, global Film Time/sample endpoints, actual measured soundtrack, original project/decision SHA, duration and explicit non-DCP/non-gapless status; max final manifest **2 MiB**.
- `backend/nvp_g09e_delivery.py`: durable `g09e_jobs` and `g09e_chunks` SQLite registers in the existing project store; one host-supervised process per active worker, **2 GiB worker RAM budget**, **32 GiB project deliverable quota**, **256 MiB minimum free-disk gate**, periodic worker heartbeat, source authorization checks, genuine process-tree cancellation and a strict one-at-a-time per-project job. An interrupted process never automatically becomes a successful movie. Restart leaves completed reels and independent verification receipts intact; a new **human-initiated Resume** revalidates the source and every reused reel. If a crash occurs between verified-file publication and the DB commit, the host independently verifies and adopts only identical, source-bound orphaned reels. An analogous exact-byte final-manifest recovery handles a crash between manifest hardlink and durable `completed` status.
- Worker custody: existing Windows Job Object with suspended-before-execution assignment and kill-on-close; Linux supervised process-tree launcher and memory limit, with future Linux cgroup-v2 custody acceptance required for escape-capable descendants. No independent actual device/OS acceptance has been run.

**E5 — Filmmaker controls / protected behavior**
- `backend/nvp_g09e_routes.py` / `backend/nvp_api.py`: authenticated project-scoped long-film start, status, director-confirmed cancel, explicit human restart/resume, verified manifest download and individual verified reel download. The film model cannot publish/authorize its own render. Only first-party project/job/reel identifiers and fixed worker actions are accepted.
- `frontend/src/DirectorLongFilmExport.jsx`, `director-long-film-export.css`, `DirectorExportFilm.jsx`: a saved film above 30 seconds displays **Finish a Longer Film**. The director sees elapsed source length, verified reel count/percent, original-source status, Stop, Resume and downloadable manifest/reels. The existing G08 short-film export remains unchanged. `DirectorFinishingRoom.jsx` preserves approved final color/sound decisions on long films but disables the older full-program 30s in-memory audition to avoid violating the new memory boundaries.
- **G03 protected encrypted movies are deliberately rejected by the ordinary G09-E disk worker.** A sealed long-film worker must encrypt all chunk outputs/checkpoints and use independent protected process/cryptographic custody before enabled. No unauthorized decrypted original is written to disk, and no automatic permission downgrade is allowed.

## Explicit remaining work, not claimed as verified

1. **No actual 30-minute film pass yet.** First objective in the deferred consolidated acceptance: at least 30 continuous minutes, authentic original scene/camera/actor motion and sound, exact 43,200 picture frames and 86,400,000 stereo audio samples per channel, 180 independently checked 10-second reels, shutdown/restart and resumed bit-for-bit source-reel consistency. Measure actual CPU/RAM/IO, storage limits, long-running host session lifetime and picture/sound continuity.
2. **No physical 60–90 minute or three-hour feature has rendered.** Code can represent up to three hours of bounded reels, but physically producing and independently reviewing those films remains open. Multi-project concurrency, explicit source chunk ownership, Windows Radeon Pro R9700 and protected original authorization must be tested on installed Windows. Particularly long single microphone Take (over 64 MiB) is rejected by the current full-clip reader; incremental original BLOB slice verification is not implemented. This is *not yet arbitrary-source-size bounded memory*.
3. **No continuous single-file playback/delivery.** Reels are individually playable AVI; no gapless cross-reel device playback or portable self-contained film package is claimed. G09-F needs a verifiable packaged viewer or native transport that uses the global clock and original manifest, safe distribution, and persistent link handling for relocated projects.
4. **Long-film encrypted source custody remains blocked.** Current G03 encrypted 30s in-memory export does not prove independently isolated AES-GCM chunk assets at feature length; G09-E's ordinary worker never handles locked-project plaintext. Finish the sealed worker/migration/process-tree recovery and owner refusal acceptance.
5. **Installed worker bootstrap is an open integration obligation.** Source-mode worker runs from a fixed `tools.nvp_g09e_worker` module; an installed frozen NVP binary must explicitly dispatch the `--g09e-worker` subcommand and bundle the vetted dependencies. This was not packaged or exercised; no installed success claim is made.
6. **No high-quality/mastering upgrade.** MJPEG is 8-bit SDR 640×360 with original-derived PCM16. Professional color-managed 4K OpenEXR/Hydra/Cycles, true-peak multi-stem sound and SMPTE Bv2.1 DCP remain G09-D2–D7 requirements. No producer acceptance or false cinema quality labels.
7. **No exact-head CI/PR/regression/physical acceptance.** Build-first instructions defer all consolidated source repair, installer and physical acceptance until the NVP backlog has been authored. Long-film current source is untested and must be reconciled before use in a real production.
