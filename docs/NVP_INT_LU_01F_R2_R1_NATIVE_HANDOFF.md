## Actual integration surface inspected

- `backend/nvp_production_journal.py` genuinely owns `ProductionJournal.status(job_id)`, `request_cancel(job_id, authorize=...)`, `reconcile_after_restart()` and `SingletonSupervisor` custody. The exact first worker is `TASK_KIND="VERIFY_APPROVED_MEDIA_V1"`: **read-only source-media integrity**, NOT finished cinema export or photoreal LTX. A native job is a UUIDv4, and its verified manifest binds the project, source and task.
- `backend/nvp_production_supervisor.py` genuinely owns `ProductionSupervisor.run_one()` inside `_require_owner` scope and confirms cancellation only after native owner checkpoint/exit; the production link does not invoke `run_one` itself, because that would dequeue another job not bound to the Lu operation.
- `backend/nvp_w1g_protected_native_worker.py` genuinely owns separately pinned first-party `ProtectedNativeWorker.run`, `cancel` and `reconcile`; its `scene_render` is a finite test slice and cannot substitute for NVP's protected LTX movie-worker contract.
- `backend/nvp_post01f_installed_receipt_transport.py` and `nvp_post01f_scm_cng_v2.py` require protected Windows EFS and independently pinned CNG signer/nonce custody for creator-approved LTX. This candidate **does not** pretend production status or a process exit constitutes one of these signed receipts.
- `backend/nvp_lu_win32_client.py` can observe a real Lu named-pipe server/process lease but explicitly cannot enroll `nvp.film` or authenticate Core without a separately accepted installed broker. This restriction remains in place.

## Changes

1. **Durable native cross-journal map (v2):** `ipc_native_jobs` records `operation_ref`, claimed unique dispatch token, exact original request digest, native job UUID, project and manifest digest. An installed NVP owner must independently witness the production job before binding it. Duplicate identical binding is idempotent; different job, operation or manifest is refused. Transactions are SQLite WAL/FULL. If the process dies between effect dispatch and binding, the existing operation remains `UNCERTAIN` and is NOT retried.
2. **Windows-specific protected production link:** `WindowsProtectedProductionLink` demands *actual* `ProductionJournal`, `ProductionSupervisor`, correct shared object and native held supervisor lock. It checks the protected native job status/revision/manifest and the original Lu user-turn/project scope on every access. Only this link calls the existing `ProductionJournal.request_cancel(..., authorize=...)`, using the native creator authorization callback. `signal_recorded` means durable signal, never claimed worker exit or reversal. Native host restart reconciliation invokes the *actual* `ProductionJournal.reconcile_after_restart()` under the owner lease.
3. **Protobuf provider handoff:** `NvpLuProviderBridge.supervisor_bind_native_production_job` is an owner-only method, never a Protobuf command. When a genuine production link has been constructed it routes `CancelOperation` into the original production journal **once**, not both generic and production cancels. It requires the existing per-turn admitted session before handling a request. The normal absent-link path remains conservative.
4. **Bound full-duplex frame loop:** `BoundNativeProviderExchange.one_exchange` uses the existing 4-byte big-endian length + <=256 KiB `lu.workspace.v0.WorkspaceFrame`, 3-second bounded partial read/write, and repeats native owner/session verification before and after processing. Rejected/abrupt frames close their borrowed pipe/socket and drop volatile stream credits, not durable operation history. It is **only a receive loop for a pre-admitted owner stream**, not a listener or an OS trust broker.
5. **Tests:** Native identity/status/tamper/duplicate/restart/unsigned-receipt/cancel-source tests, provider-to-production path with explicitly synthetic owner, and OS-local Linux socketpair transfer. All Windows-specific positive tests remain blocked until actual Windows custody and installed broker provision exist.

## Safety boundaries retained

Use the exact Lu `LuWorkspaceProvider` `Invoke`/`Cancel`/`Reconcile` and NVP `nvp.film.v1` typed payloads. No gRPC/TCP/JSON fallback, unreviewed synthetic credential, UI-supplied job ID, shell executor, automatic creator approval, model-side LTX approval, original Take/PCM mutation, second model server, or replay of dispatched work. No `PRODUCTION_DCP_ACCEPTED` or terminal `APPLIED` from read-only verification status. The full mixed `EXECUTE + WRITE_WORKSPACE` effect classes must be accepted by Lu Core **before** any render/export capability is registered for production. An operation receipt digest is a locator; not a cryptographic proof by itself.
