# G08 — Native Export Film implementation

**Development branch:** `nvp/g08-native-film-export-20261111` stacked on G07's immutable source edit assembly. **Build-first status: source implementation, NOT installed/native acceptance.** No CI, PR verification, regression or owner-operated film playback was performed.

## Filmmaker experience

Film Home's fifth step, **Export Film**, is now active. The director sees film length, shot count, and an ordinary **Finish and Save Movie** action, not worker processes, data formats or command lines. NVP requests direct confirmation before preparing an export. The project-access lock gate continues to apply. The screen shows progress, permits **Stop Export**, preserves earlier deliverables, gives a final **Save Movie** link only after verification, and identifies interrupted/failed attempts without altering original film content. The first delivery deliberately supports **up to 30 seconds**, trimmed on 24 fps picture boundaries.

The output is a real **640×360 24fps AVI** with first-party interleaved **MJPEG picture + original-source mixed 48kHz stereo PCM16 sound**. MJPEG uses the independent Pillow/libjpeg JPEG codec; NVP authors its own AVI/RIFF interleaving, container metadata and index. Neither FFmpeg nor libav is used in this implementation. **The picture is a deliberately bounded low-poly 3D film render** from actual G05/G06 OpenUSD world objects and exact-time G07 camera/cut/grade choices; it is *not* a photoreal Cycles production renderer. Full film visual/voice/acoustic quality and long-form delivery remain G09.

The default first 30-second export is exactly **720 source-evaluated picture samples** and **1,440,000 original-time audio samples per channel**, with samples interleaved continuously at 2000 per output picture frame. Frame/sample cadence is an export projection: Film Time (7,056,000,000 ticks/second), original OpenUSD performance, original PCM and frozen Takes remain authoritative and unchanged.

## Engineering source

- `backend/nvp_g08_native_avi.py`: first-party native OpenUSD time-evaluated primitive renderer (cube/sphere/cone/cylinder), scene camera projection, light-responsive shaded geometry, per-shot color decisions and cut/dissolve evaluation; exact G07 audio mixing from original verified mono PCM with spatial source/pan/gain and crossfade; bounded streaming MJPEG/PCM AVI writer. It refuses unsupported geometry, unknown film formats, invalid durations, output beyond bounded size and incomplete audio.
- `tools/nvp_g08_export_worker.py`: fixed source-only render/independent-verify worker, reopens exact G07 edit SHA and all referenced G06 originals from the source project database, never accepts arbitrary picture uploads or caller-selected output paths. Separate verify mode decodes **every JPEG picture** and validates each contiguous PCM audio chunk and the movie index.
- `backend/nvp_g08_export.py`: ordinary movie export manager with durable Studio SQLite journal, job states, frame-progress receipt, same-project one-export rule, restart reconciliation (incomplete work becomes **interrupted**, never falsely completed), director cancellation, bounded worker runtime and fixed subprocess executed under existing NVP OS containment. On Windows it uses native Job Object custody; Linux uses existing parent-custodied process supervisor. A final movie filename is **not** published until separate-process verification succeeds and a no-overwrite same-filesystem publication succeeds. Every download independently checks output size and SHA against the verified receipt. Original Takes/edits are never overwritten.
- `backend/nvp_g08_sealed_export.py`: distinct encrypted-film path. G07's approved source is read through existing protected G03 in-memory SQLite; native picture and sound are evaluated in-memory; only the verified derived movie is sealed as an **AES-GCM encrypted G08 derivative asset** through the existing protected-film key and authenticated readback. The host never writes decrypted film or the finished movie to an ordinary pathname. The persistent job index lives in sealed SQLite; volatile progress can be lost on crash, and an interrupted job is reconciled conservatively after movie unlock. Cancellation is project-scoped. This in-process protected path is **not** an OS sandbox or separately isolated verifier.
- `backend/nvp_g08_routes.py` + `backend/nvp_api.py`: director-session-guarded create/status/cancel/download, existing project-lock checks, same-origin read-only downloads, secured movie output path and lock-triggered cancellation. The WebView provides no arbitrary filesystem path, executable, shell, worker key or unreviewed script.
- `tools/nvp_desktop_alpha.py`: installed NVP executable dispatches the fixed internal export worker command in subprocess mode, not the developer's uninstalled Python interpreter.
- `frontend/src/DirectorExportFilm.jsx`, `director-export-film.css`, and `FilmmakerHome.jsx`: replace disabled Export Film placeholder with native-source delivery and creative-only controls.

## What is **not** claimed complete

1. **No real 30-second owner film was produced or inspected in this source-only work.** The first actual film run, real loaded USD/PCM/GGUF inputs, Windows NSIS app, real Radeon viewport/frame pacing, multiple camera cuts, stereo continuity, independent player playback and failure matrix remain for later consolidated native/installed acceptance under the creator's build-first policy. A source implementation is not acceptance evidence.
2. **First profile only.** 640×360 MJPEG + 48kHz PCM AVI is a valid first-party moving-picture/audio delivery design, but is neither a finalized cinema-quality master nor the intended ProRes/DCP feature delivery. G09 handles 1080p/4K, quality shaders, true complex meshes/actors, multichannel sound, longer films and theatrical mastering; no FFmpeg is introduced.
3. **Protected export:** in-memory host processing prevents plaintext derivative files; final output uses authenticated AES-GCM. However it does *not* claim independently isolated native sandbox/second-process verification, owner-tested key custody or crashed-thread full recovery. G03 protected-worker hardening and installed security acceptance remain open. Do not state that either is approved for release.
4. **Interrupted exports:** ordinary worker process custody and cancellation are implemented in source; restart makes incomplete exports retryable from unchanged originals, not resumed mid-frame from an unverified partial file. The source code does not yet implement checkpoint-resumable frame production. The protected path also restarts from scratch, never silently publishes interrupted work.
5. **Independent proof:** ordinary export has separate process decode for all frames and PCM lengths. Protected film performs in-memory decode and sealed authenticated readback; separate OS isolation/verification are still required for production acceptance.
6. **Creative quality:** model-directed screenwriting/production and actor performance may be only semantic source with simple low-poly visualization; no fake "animated acting" or simulated audio is passed off as production-quality authored performance.
